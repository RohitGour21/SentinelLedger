# SentinelLedger

Flask audit-logging and security-monitoring application with SHA-256 hash-chained
audit logs, role-based access control (Admin / Security Analyst / Viewer),
threat detection rules and API monitoring. The database is **SQLite**
(Python's built-in `sqlite3`); no database server is required.

## Run locally

```bash
python -m venv venv
venv\Scripts\activate          # Windows   (Linux/macOS: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env         # then edit .env and set FLASK_SECRET_KEY
python create_admin.py         # creates the first Admin
python app.py
```

The database file (`sentinel_ledger.db`) and all tables, roles and default
security rules are created automatically on first use.

## Environment variables

Never commit real values. Copy `.env.example` to `.env` locally; on Render set
them in the dashboard.

| Variable | Required | Purpose |
|---|---|---|
| `FLASK_SECRET_KEY` | Yes | Flask session / CSRF signing key. Use a long random value. |
| `SESSION_COOKIE_SECURE` | No (default `False`) | Set `true` when served over HTTPS (Render). |
| `DATABASE_PATH` | No | Path of the SQLite file. Default: `sentinel_ledger.db` next to `app.py`. |
| `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_EMAIL` / `INITIAL_ADMIN_PASSWORD` | No | If all three are set and no user exists, an Admin is created at start-up. Needed on Render's free tier, which has no shell for `create_admin.py`. Password: 12+ characters. |

## Deploy to Render (free)

1. Push this repository to GitHub (`.env`, `venv/` and `*.db` are git-ignored).
2. In Render choose **New → Blueprint** (uses `render.yaml`), or **New → Web Service** with:
   - Build command: `pip install -r requirements.txt`
   - Start command: `gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`
3. Set the environment variables above (`FLASK_SECRET_KEY` is generated by the blueprint).
4. Deploy, then sign in with the initial Admin.

Notes:
- Render's free filesystem is temporary: the SQLite database (users, audit logs, events)
  is **reset on every restart/redeploy**. The initial Admin is re-created from the
  `INITIAL_ADMIN_*` variables each time.
- Use a single worker: SQLite is one file.
- `wsgi.py` exists because the project has both `app.py` and an `app/` package, so
  `gunicorn app:app` would import the package instead of `app.py`.

## Tests

`python test_sqlite_e2e.py` runs an end-to-end suite against a temporary database
(login, roles, dashboard, audit chain, tamper detection, threat rules, API monitor).

## Database notes

- `database/schema.sql` – SQLite schema + reference data (roles, default security rules).
- `database/schema_mysql.sql` – the original MySQL schema, kept for reference.
